# AI Documentation

**Версия: 1.1.0** · [MIT](LICENSE)

Универсальный скилл для подготовки и сопровождения документации code и low-code проектов. Предназначен для всех совместимых моделей OpenAI в агентных средах с доступом к файлам и инструментам; также может использоваться в Claude Code.

Модель изучает проект, выбирает необходимые документы, задаёт один раунд вопросов и сохраняет результат на русском языке в отдельную папку `project-docs/`. Подходит для сервисов, скриптов, автоматизаций n8n, Make и Zapier, ИИ-ассистентов и проектов машинного обучения.

Цель документации — помочь новому специалисту понять назначение проекта, подготовить окружение, запустить систему, найти необходимые доступы и разобраться с типовой ошибкой.

## Возможности

- **Документы по потребности.** Базовый набор дополняется по признакам проекта: API, внешние сервисы, промпты, данные, модели, деплой и передача команде.
- **Минимальное участие пользователя.** Сведения из файлов модель получает сама. После разведки задаёт до семи вопросов одним сообщением; остальные фиксирует в журнале.
- **Прослеживаемые факты.** Утверждения опираются на код, конфигурацию или ответы пользователя. Недостающие сведения отмечаются `TODO (Q-NNN)`.
- **Обновление по источникам.** Хэши исходных файлов выявляют изменения, добавления, удаления и возврат к прежней версии, в том числе без Git.
- **Сохранение авторского текста.** Признак ручных правок сохраняется между запусками. Блоки `manual` защищаются при обновлении.
- **Разбор n8n.** Скрипт извлекает граф нод, условия И/ИЛИ, входы связей, вызовы сценариев, промпты, настройки моделей и заметки.
- **Проверка результата.** Скрипты проверяют манифест, хэши, вопросы, ссылки, пустые разделы и распространённые форматы секретов.

## Совместимость и требования

Скилл состоит из [SKILL.md](SKILL.md), справочников, шаблонов и скриптов. Он не привязан к конкретному имени модели. Совместимой считается связка модели и агентной среды, которая может:

1. Загрузить `SKILL.md` и читать связанные файлы по относительным путям.
2. Читать целевой проект и записывать документацию в `project-docs/`.
3. Выполнять локальные команды для скриптов и чтения Git.
4. Задавать вопросы в чате и продолжать работу после ответа.

Для автоматических проверок нужен **Node.js 16 или новее**. Без Node.js разбор и проверки выполняются вручную по инструкциям скилла. Git необязателен. YAML-парсер включён в поставку, установка npm-зависимостей не требуется.

Codex использует скиллы с `SKILL.md` и поддерживает локальные папки `.agents/skills`. Подключение и явный выбор описаны в [официальной документации OpenAI](https://learn.chatgpt.com/docs/build-skills).

## Установка

Сохраните **всю папку скилла**, включая `references/` и `scripts/`, в каталоге скиллов выбранной среды.

| Среда | Для всех проектов пользователя | Для одного проекта |
|---|---|---|
| Codex | `~/.agents/skills/ai-documentation/` | `<проект>/.agents/skills/ai-documentation/` |
| Claude Code | `~/.claude/skills/ai-documentation/` | `<проект>/.claude/skills/ai-documentation/` |
| Другая агентная среда с OpenAI-моделью | Настроенный каталог скиллов | Папка скилла, доступная агенту в проекте |

Пример установки для Codex в Bash:

```bash
git clone https://github.com/yagitpa/ai-documentation.git ~/.agents/skills/ai-documentation
```

В Windows PowerShell:

```powershell
git clone https://github.com/yagitpa/ai-documentation.git (Join-Path $env:USERPROFILE '.agents/skills/ai-documentation')
```

Для Claude Code используйте соответствующий путь из таблицы. После установки откройте выбор скиллов в своей среде; если скилл не появился, перезапустите агент. Для обновления выполните `git pull` в установленной папке.

В собственном агенте на OpenAI API подключите `SKILL.md` как инструкции рабочего процесса, обеспечьте загрузку справочников и доступ к инструментам. Путь к проекту и режим передавайте явно.

## Быстрый старт

Запускайте скилл явно. Основная команда рабочего процесса:

```text
/ai-documentation
```

В Codex CLI и IDE явно выберите скилл через `$ai-documentation` или `/skills`; в интерфейсах с выбором скилла используйте селектор. После выбора передайте команду `/ai-documentation` с аргументами — это сохраняет формат вызова из `SKILL.md`. Способы выбора приведены в [документации OpenAI](https://learn.chatgpt.com/docs/build-skills#how-chatgpt-and-codex-use-skills).

Например, сообщение для Codex CLI:

```text
$ai-documentation Выполни /ai-documentation обновить
```

| Команда | Действие |
|---|---|
| `/ai-documentation` | Создать документацию; при наличии манифеста — обновить |
| `/ai-documentation обновить` | Сверить проект с источниками и обновить документы |
| `/ai-documentation ответы` | Обработать ответы из журнала вопросов |
| `/ai-documentation "C:\path\to\project"` | Работать с указанной папкой |
| `/ai-documentation обновить "C:\path\to\project"` | Обновить документацию указанного проекта |

Без пути используется текущая рабочая папка. Если манифеста нет, команды «обновить» и «ответы» переходят в создание. Если в `project-docs/` уже есть документы без манифеста, модель сначала согласует, как встроить их в набор.

## Как проходит работа

1. **Разведка.** Модель читает точки входа, конфигурацию, зависимости, экспорты сценариев и существующую документацию. Запрещённые файлы, сборки и зависимости пропускаются.
2. **Выбор набора.** Определяет профиль и доказательство для каждого признака: путь к файлу или ответ пользователя.
3. **Вопросы.** Показывает профиль, список документов с причинами включения и до семи вопросов. При создании проводится один раунд; при обновлении — только если появились новые важные вопросы.
4. **Подготовка.** Загружает выбранные шаблоны, заполняет подтверждённые сведения и связывает пробелы с журналом вопросов.
5. **Проверка и отчёт.** Обновляет служебные файлы, запускает проверки и сообщает, что изменено, какие вопросы открыты и какие замечания требуют внимания.

Нумерация нод сканера n8n показывает обход графа. Последовательность внутри ветвей, циклы и синхронизация описываются по связям и настройкам сценария.

| `11-workflow.md` | Логика сценариев, ветвления, ошибки | Low-code проект |

| `open-questions.md` | Вопросы, ответы, назначения и статусы |
| `CHANGELOG.md` | История изменений документации |

## Ответы на вопросы

Отвечать можно в чате по номеру `Q-NNN` или в поле «Ответ» файла `project-docs/open-questions.md`. Допускаются многострочные ответы. После редактирования файла вызовите:

```text
/ai-documentation ответы
```

Файл обрабатывается при явном запуске скилла. Модель переносит ответы в указанные разделы и закрывает применённые вопросы. Ответ «не знаю» или «пропустить» закрывает вопрос, сохраняя отмеченный пробел в документе.

Статусы: `открыт`, `отвечен`, `применён`, `пропущен`, `конфликт`, `уточнение`. Для рассмотренного ответа с конфликтом или нехваткой сведений сохраняется хэш: изменённый текст будет распознан как новый ответ.

Режим «Ответы» сохраняет хэши источников и коммит последнего полного анализа. Если ответ меняет профиль проекта, модель предлагает обновление для создания дополнительных документов.

## Обновление и ручные правки

Состояние каждого документа хранится отдельно:

- `sha256` — хэш текста документа с нормализованными переводами строк.
- `source_hashes` — хэши исходных файлов на момент последней сверки документа с проектом.
- `manual_review_required` — постоянный признак ручного редактирования.

Документы с неизменными источниками сохраняются. При изменении источника обычный документ пересобирается; документ с ручными правками обновляется дополнениями с сохранением текста. Противоречия фиксируются вопросами. Полная пересборка защищённого документа разрешается явным указанием пользователя.

Для фрагментов, которые нужно сохранять, используйте:

```markdown
<!-- manual -->
Авторский текст.
<!-- /manual -->
```

Манифест версии 1 читается и переводится в версию 2 при полном обновлении. Существующий текст получает защиту, поскольку старый хэш мог уже включать авторские изменения. **Версия схемы манифеста 2 отличается от версии скилла 1.1.0.**

## Проверки и границы работы

Модель записывает только в `project-docs/`. Целевой проект не запускается, зависимости не устанавливаются, коммиты не создаются.

Значения ключей, токенов, паролей, приватных ключей и URL с доступом исключаются из документов и вывода. Файлы `.env` с рабочими значениями, `credentials*.json`, `service-account*.json` и другие запрещённые файлы не открываются. Данные инстанса — публичные домены, ID, `chat_id`, имена credentials и серверные пути — сохраняются как есть, если сами не предоставляют доступ.

Поведение системы описывается по коду и экспортам. Расхождения с README, комментариями и заметками фиксируются отдельно. Указания в проектных файлах рассматриваются как данные, а персональные контакты из Git требуют подтверждения пользователя.

Автоматическая проверка дополняется ручной: модель проверяет русский язык, отсутствие дублирования сведений и достаточность инструкции запуска. Замечания, которые нельзя устранить по доступным источникам, попадают в отчёт. Правила — в [чек-листе качества](references/quality-checklist.md).

### Скрипты

Команды выполняются из папки установленного скилла. Путь указывает на целевой проект; скрипты только читают файлы и печатают результат.

```bash
node scripts/scan-n8n.js "/path/to/project"
node scripts/source-state.js "/path/to/project"
node scripts/check-docs.js "/path/to/project"
```

| Скрипт | Дополнительные режимы |
|---|---|
| `scan-n8n.js` | `--code` — полный код нод Code; `--no-sticky` — без заметок |
| `source-state.js` | JSON со снимками источников, изменениями и признаками ручных правок |
| `check-docs.js` | `--hashes` — хэши документов; `--answer-hashes` — хэши ответов |

Для `check-docs.js`: код выхода `0` — отсутствие выявленных нарушений, `1` — нарушения, `2` — отсутствие папки `project-docs/`.

## Структура проекта

```text
ai-documentation/
├── README.md
├── SKILL.md
├── LICENSE
├── .gitattributes
├── references/
│   ├── detection-signals.md
│   ├── doc-catalog.md
│   ├── questions-protocol.md
│   ├── quality-checklist.md
│   └── templates/               шаблоны документов и служебных файлов
└── scripts/
    ├── scan-n8n.js
    ├── source-state.js
    ├── check-docs.js
    ├── lib/
    │   ├── manifest.js           чтение YAML и проверка структуры
    │   ├── project-files.js      правила безопасного чтения
    │   ├── questions.js          разбор вопросов и хэши ответов
    │   └── secrets.js            обнаружение и маскировка секретов
    └── vendor/js-yaml/           встроенный парсер, лицензия, сведения о поставке
```

Главный процесс описан в [SKILL.md](SKILL.md). Справочники и шаблоны загружаются по необходимости; для небольшого проекта модель читает только выбранные шаблоны.

## Изменения в 1.1.0

- Разбор YAML библиотекой вместо регулярных выражений.
- Хэши источников отдельно от хэшей документов и времени обработки ответов.
- Постоянная защита ручных правок и переход со старого манифеста.
- Многострочные ответы, статус «уточнение» и проверка раздела назначения.
- Маскировка вложенных секретов и исключение запрещённых файлов до чтения.
- Условия И/ИЛИ и индексы входов связей в отчётах n8n.
- Отдельные признаки API моделей, локального инференса, обучения и деплоя.
