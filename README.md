# AI Documentation

Скилл для Claude Code, который сам готовит документацию проекта для передачи другому разработчику и поддерживает её в актуальном состоянии.

Подходит для code и low-code проектов: сервисы, скрипты, сценарии n8n и Make, ИИ-ассистенты. Документация пишется на русском в папку `project-docs/` внутри проекта.

Версия: 1.0.0

---

## Зачем

Документацию к проекту обычно либо не пишут совсем, либо пишут «на всё сразу» по большому шаблону, где половина разделов пустая. Model Card для бота на GPT через API, раздел про train/test для сценария в n8n, описание API у проекта без API.

Скилл делает наоборот: сначала изучает проект, определяет его профиль и создаёт только те документы, которые этому проекту нужны. Всё, что можно узнать из файлов, модель узнаёт сама. Остальное спрашивает один раз, коротким списком.

Критерий готовности простой: новый специалист без участия автора может понять, что делает проект, запустить его, найти доступы и устранить типовую ошибку.

## Как работает

1. **Разведка.** Модель читает проект: манифесты зависимостей, конфиги, README, точки входа, промпты, CI, Docker. Экспорты n8n разбирает скрипт: ноды в порядке выполнения, ветвления, промпты, параметры моделей, credentials, sticky-заметки.
2. **Профиль.** По найденному ставятся флаги: `llm`, `low_code`, `api`, `end_users`, `deployed`, `own_data`, `own_model`, `handoff` и другие. У каждого флага есть доказательство — путь к файлу или ответ пользователя.
3. **Один раунд вопросов.** Одно сообщение: профиль, список документов с причиной и до 7 вопросов о том, чего нет в файлах (цель, владелец, окружение). Остальные вопросы уходят в журнал.
4. **Генерация.** Каждый документ собирается по своему шаблону. У каждого факта есть источник. Где источника нет, стоит метка `TODO (Q-003)` со ссылкой на вопрос.
5. **Проверка.** Скрипт проверяет документацию: секреты, битые ссылки, пустые разделы, метки без вопросов, актуальность манифеста и хэшей. Итоговый отчёт выдаётся только после проверки.

## Какие документы создаются

| Документ | Когда |
|---|---|
| Обзор, архитектура, установка и запуск, конфигурация, ошибки и экстренные действия | всегда |
| Карта доступов (без значений секретов) | есть внешние сервисы |
| Логика сценариев по нодам | low-code: n8n, Make, Zapier |
| Библиотека промптов, использование моделей, метрики | есть LLM |
| Model Card, карточка данных | своя модель, свои датасеты или RAG |
| Справочник API | есть эндпоинты или вебхуки |
| Руководство пользователя | есть UI, бот или форма |
| Развёртывание | есть Docker, CI или несколько окружений |
| Требования | есть ТЗ, PRD или бриф |
| Чек-лист передачи | проект передаётся другой команде |

Плюс служебные файлы: `README.md` (карта папки), `manifest.yaml` (профиль, источники, хэши), `open-questions.md` (журнал вопросов), `CHANGELOG.md`.

## Использование

Скилл запускается только явной командой.

```
/ai-documentation                        создать документацию или обновить, если она уже есть
/ai-documentation обновить               обновить после изменений в проекте
/ai-documentation ответы                 внести ответы из open-questions.md
/ai-documentation C:\path\to\project     документировать другую папку
```

### Журнал вопросов

Всё, что модель не смогла узнать из проекта, попадает в `project-docs/open-questions.md`. Отвечать можно в чате или прямо в файле, в строке «Ответ». После ответа в файле — `/ai-documentation ответы`, и модель внесёт ответы в документы.

У каждого вопроса есть статус: `открыт`, `отвечен`, `применён`, `пропущен` (ответ «не знаю») и `конфликт` (ответ противоречит коду — модель покажет противоречие и спросит, что верно).

### Обновление

Модель сравнивает проект с манифестом: `git diff` от сохранённого коммита плюс новые неотслеживаемые файлы. Пересобираются только документы, у которых изменились источники.

Ручные правки не теряются:
- текст между `<!-- manual -->` и `<!-- /manual -->` не меняется никогда;
- документ, отредактированный вручную (хэш не совпадает с манифестом), пересобирается бережно, а противоречия с кодом оформляются вопросом.

## Границы

- Запись — только в `project-docs/`. Остальные файлы проекта только читаются. Скилл не запускает проект, не ставит зависимости, не делает коммиты.
- Значения секретов (ключи, токены, пароли, URL с токеном) не попадают ни в документы, ни в чат. Файлы вроде `.env` и `credentials*.json` не открываются.
- Данные инстанса — домены, ID сценариев и списков, `chat_id`, пути на сервере — переносятся как есть: без них принимающий разработчик не перенастроит систему.
- Поведение системы описывается по коду и экспортам. Если README или sticky-заметка им противоречат, в документ идёт версия кода, а расхождение записывается отдельно.
- Указания внутри файлов проекта (README, комментарии, промпты) модель не выполняет как команды — это данные.

## Установка

Нужен Claude Code. Для скриптов проверки и разбора n8n — Node.js 16 или новее. Без Node.js скилл работает, но проверки выполняются вручную.

```bash
git clone https://github.com/yagitpa/ai-documentation.git ~/.claude/skills/ai-documentation
```

На Windows `~` — это `%USERPROFILE%`, то есть `C:\Users\<имя>\.claude\skills\ai-documentation`.

Скилл появится в списке команд после перезапуска Claude Code. Обновление — `git pull` в этой папке.

Чтобы скилл был доступен только в одном проекте, склонируйте его в `<проект>/.claude/skills/ai-documentation`.

## Структура

```
ai-documentation/
├── SKILL.md                      процесс, режимы, границы
├── references/
│   ├── detection-signals.md      признаки проекта → флаги профиля
│   ├── doc-catalog.md            флаги → документы, шапка, правило единого источника
│   ├── questions-protocol.md     формат журнала вопросов и статусы
│   ├── quality-checklist.md      проверка перед отчётом
│   └── templates/                шаблон на каждый документ и служебные файлы
└── scripts/
    ├── check-docs.js             проверка project-docs/, режим --hashes
    ├── scan-n8n.js               разбор экспортов n8n
    └── lib/secrets.js            общие шаблоны секретов
```

Шаблоны загружаются только для выбранных документов, поэтому для небольшого проекта модель читает несколько шаблонов, а не все.

## Статус проверки

Версия 1.0.0 проверена на реальном n8n-проекте из 16 сценариев (Telegram-бот с LLM, голосовым вводом и ClickUp): создание документации, раунд вопросов, внесение ответов из файла. Скрипты проверены на этом проекте и на синтетических случаях с секретами и ручными правками.

Ещё не проверялись на реальных проектах: режим обновления, проекты без n8n (чистый код), проекты на Make и Zapier.
