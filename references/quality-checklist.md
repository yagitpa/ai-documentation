# Проверка перед отчётом

Выполняется на шаге 6. Каждый пункт даёт наблюдаемый результат. Нарушение исправляется или записывается в отчёт в раздел «Предупреждения».

Пункты 1–8 и 12 автоматизированы: `node <папка скилла>/scripts/check-docs.js <корень проекта>`. Скрипт выводит нарушения с номером пункта и файлом. Совпадение по секретам (пункт 1) скрипт показывает без значения — строку нужно открыть и оценить. Пункты 9–11 проверяются вручную.

1. Секреты. Поиск по `project-docs/` шаблонов: `sk-`, `sk-ant-`, `ghp_`, `gho_`, `xox[bp]-`, `AKIA`, `AIza`, `Bearer `, `-----BEGIN`, а также `password`, `token`, `api_key`, `secret` с непустым значением после `=` или `:`. Результат: 0 совпадений со значениями. Совпадения на именах переменных допустимы.
2. Состав. Файлы документов совпадают с набором из `manifest.yaml`: нет пропущенных и нет лишних. Исключение — файлы, существовавшие до скилла.
3. Шапка. Каждый документ начинается с шапки из `doc-catalog.md`. Каждый путь в «Источниках» существует в проекте.
4. TODO. Каждый `TODO` содержит `Q-NNN`, и этот вопрос есть в `open-questions.md` со статусом `открыт`, `конфликт` или `пропущен`. Статус в шапке соответствует числу меток: «заполнен» при 0, «черновик, пробелов: N» при N > 0.
5. Вопросы. Каждое поле «Куда пойдёт ответ» указывает на существующий файл и раздел.
6. Ссылки. Каждая относительная ссылка ведёт на существующий файл.
7. Пустые разделы. Нет заголовка, за которым сразу идёт другой заголовок или конец файла.
8. Следы шаблона. Нет комментариев `<!-- g:` и `%% g:`.
9. Единый источник. Переменные, схема хранилища, доступы, метрики и тексты промптов описаны только в своих документах по `doc-catalog.md` → «Единый источник».
10. Язык. Текст документов на русском. Идентификаторы и литералы из проекта оставлены как есть.
11. Проверка передачи. По `03-setup-and-run.md` можно пройти путь от нуля до работающего проекта:
    - есть предусловия;
    - есть шаги или команды, каждая из которых взята из проекта или является стандартной командой обнаруженного менеджера пакетов;
    - есть признак успешного запуска.

    В `06-troubleshooting.md` есть способ остановить систему. Если чего-то нет, на этом месте стоит `TODO` с важным вопросом.
12. Служебные файлы.
    - `updated_at` в манифесте — полные дата и время, `git_commit` совпадает с `git rev-parse HEAD` (если есть git);
    - `sha256` каждого документа в манифесте совпадает с текущим хэшем файла;
    - верхняя запись `CHANGELOG.md` датирована днём из `updated_at`;
    - счётчик открытых вопросов в `README.md` совпадает с `open-questions.md`.
