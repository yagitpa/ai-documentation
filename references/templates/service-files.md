```markdown
## Как обновлять
Документация генерируется скиллом ai-documentation. После изменений в проекте — `/ai-documentation обновить`, после ответов в [open-questions.md](open-questions.md) — `/ai-documentation ответы`. Ручной текст, который не должен перезаписываться, заключайте в `<!-- manual -->` … `<!-- /manual -->`.
```

## manifest.yaml

```yaml
version: 2
generated_at: 2026-09-30T10:15:00.000Z
updated_at: 2026-09-30T14:42:07.000Z   # время последнего запуска, из системы
git_commit: null            # HEAD последнего полного анализа; режим «Ответы» не меняет
project_type: [low_code]    # code / low_code
profile:
  llm:
    value: true
    evidence: [workflows/assistant.json]
  handoff:
    value: true
    evidence: [Q-002]
documents:
  - file: 11-workflow.md
    reason: low_code
    sources: [workflows/assistant.json]
    sha256: 3f9a…            # вывод check-docs.js --hashes
    source_hashes: {}       # при создании; затем карта из вывода source-state.js
    manual_review_required: false  # постоянный признак ручных правок
questions:
  next_id: 8
```

В `profile` записываются только выставленные флаги. Доказательством может быть путь или ID ответа.

`sources` — пути к файлам или папкам проекта, из которых собран документ. Папка означает «любой файл внутри». По этому полю режим обновления решает, какие документы пересобирать, поэтому указываются реальные источники, а не весь проект.

`sha256` — хэш документа после последнего запуска скилла, нормализованный по переводам строк. Не совпадает с текущим — документ правили вручную. Это не хэш исходного кода.

`source_hashes` — карта «путь файла → SHA256 содержимого» на момент последней сверки конкретного документа с проектом. Папки из `sources` раскрываются в файлы; отсутствие файла обозначается `null`. Значения берутся из `source-state.js`, не придумываются. При удалении файла из папки его отсутствие в новой карте выявляет изменение. Запрещённые файлы и symlink/junction не читаются. В режиме «Ответы» карта сохраняется; в «Обновлении» изменяется только для проверенных документов.

`manual_review_required` — постоянный признак ручного редактирования. Он становится `true`, если хэш документа изменился вне скилла или есть блок `manual`, и сохраняется после обновления `sha256`. Сбросить его можно только по явному указанию пользователя разрешить полную пересборку. При `true` существующий текст сохраняется, изменения источников отражаются дополнениями и вопросами о конфликтах.

Манифест версии 1 поддерживается при чтении. Переход на версию 2 выполняется только в режиме «Обновление» после сверки документов с источниками. Существующие документы версии 1 получают `manual_review_required: true`, поскольку прежний хэш мог уже включать авторский текст. YAML допускает кавычки и любой порядок ключей; библиотека парсера встроена в скилл.

## open-questions.md

Формат описан в `references/questions-protocol.md`. Если вопросов нет, файл всё равно создаётся с разделами «Открытые» и «Закрытые»; в каждом записывается «Нет вопросов», чтобы не оставлять пустых разделов.

## CHANGELOG.md

Новые записи добавляются сверху. На каждый запуск скилла одна запись. Дата записи — дата из `updated_at` манифеста этого запуска.

```markdown
# Журнал изменений документации

## 2026-09-30 · обновление
- Изменено: 11-workflow.md (новая нода «Классификатор»), 04-configuration.md
- Применены ответы: Q-003, Q-005
- Новые вопросы: Q-008
- Причина: изменения в workflows/assistant.json
```
